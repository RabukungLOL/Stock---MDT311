# ระบบสต็อกสินค้า (Stock Management System)

เว็บจัดการสต็อกสินค้า ใช้ HTML + CSS + JavaScript เชื่อมต่อฐานข้อมูล Supabase (PostgreSQL) ผ่าน supabase-js
ไม่ต้องติดตั้ง Node.js หรือ build อะไร

## โครงสร้างไฟล์

```
stock-system/
├── supabase/
│   └── schema.sql          สร้างตาราง, constraint, Trigger ตัดสต็อก, RLS และข้อมูลตัวอย่าง
└── web/
    ├── index.html          หน้าเข้าสู่ระบบ
    ├── products.html       รายการสินค้า ค้นหา กรอง ลบ
    ├── product-form.html   เพิ่ม / แก้ไขสินค้า
    ├── stock.html          รับเข้า / เบิกออก
    ├── history.html        ประวัติรับเข้า / เบิกออก
    ├── css/style.css
    └── js/
        ├── config.example.js   ตัวอย่างไฟล์ตั้งค่า (คัดลอกเป็น config.js)
        ├── app.js              ฟังก์ชันที่ทุกหน้าใช้ร่วมกัน
        ├── login.js
        ├── products.js
        ├── product-form.js
        ├── stock.js
        └── history.js
```

## วิธีติดตั้ง

### 1. สร้างฐานข้อมูล (คนที่ 1)
1. เปิดโปรเจกต์ใน Supabase ไปที่ **SQL Editor** แล้วกด **New query**
2. วางเนื้อหาทั้งไฟล์ `supabase/schema.sql` แล้วกด **Run**
3. ถ้าเคยสร้างตาราง `categories`, `products`, `stock_transactions` ไว้แล้ว Run จะขึ้นว่ามีตารางอยู่แล้ว
   ให้เปิดคอมเมนต์ 3 บรรทัด `drop table` ที่ด้านบนของไฟล์ แล้ว Run ใหม่ (ข้อมูลเดิมจะหาย)
4. ตรวจที่ **Table Editor** ต้องเห็น 3 ตาราง มีสินค้า 10 รายการ และประวัติ 15 รายการ

### 2. สร้างบัญชีผู้ใช้สำหรับเข้าเว็บ
1. ไปที่ **Authentication > Users > Add user > Create new user**
2. ใส่อีเมลและรหัสผ่าน แล้วติ๊ก **Auto Confirm User** จะได้ไม่ต้องยืนยันอีเมล
3. สร้างให้สมาชิกทุกคนในกลุ่มได้ (ห้ามใช้รหัสผ่านจริงที่ใช้กับบัญชีอื่น)

### 3. ตั้งค่าการเชื่อมต่อ
1. คัดลอกไฟล์ `web/js/config.example.js` แล้วตั้งชื่อใหม่เป็น `web/js/config.js`
2. ใส่ค่า 2 ตัว (กดปุ่ม **Connect** ด้านบนของ dashboard หรือดูใน **Project Settings > API Keys**)
   - `SUPABASE_URL` : Project URL เช่น `https://abcdxyz.supabase.co`
   - `SUPABASE_KEY` : **Publishable key** (`sb_publishable_...`) หรือ **anon public key** แบบเดิม
3. **ห้ามใส่ Secret key หรือ service_role key** เด็ดขาด

### 4. เปิดเว็บ
แนะนำให้ใช้ VS Code + ส่วนขยาย **Live Server**: คลิกขวาที่ `web/index.html` แล้วเลือก **Open with Live Server**

หรือถ้ามี Node.js ให้รันคำสั่ง `npx serve web` แล้วเปิดลิงก์ที่ขึ้นมา

ไม่แนะนำให้ดับเบิลคลิกเปิดไฟล์ HTML ตรง ๆ เพราะบางเบราว์เซอร์จะจำการล็อกอินไม่ได้

## หน้าเว็บกับ CRUD (ใช้เขียนบทที่ 4.2 – 4.3)

| กระบวนการ | หน้าเว็บ / ไฟล์ | โค้ด supabase-js ที่สำคัญ |
|---|---|---|
| **Create** เพิ่มสินค้า | `product-form.html` / `product-form.js` | `db.from('products').insert(row).select('id').single()` |
| **Create** รับเข้า / เบิกออก | `stock.html` / `stock.js` | `db.from('stock_transactions').insert({ product_id, type, quantity, note })` |
| **Read** รายการ ค้นหา กรอง | `products.html` / `products.js` | `db.from('products').select('..., categories(name)').or('name.ilike.%คำค้น%,sku.ilike.%คำค้น%')` |
| **Read** ประวัติ | `history.html` / `history.js` | `db.from('stock_transactions').select('..., products(sku, name, unit)').order('created_at', { ascending: false })` |
| **Update** แก้ไขสินค้า | `product-form.html?id=…` / `product-form.js` | `db.from('products').update(row).eq('id', editId)` |
| **Update** ยอดคงเหลือ | Trigger `apply_stock_transaction` ใน `schema.sql` | ฐานข้อมูลปรับ `stock_quantity` เองเมื่อมีรายการรับเข้า/เบิกออก |
| **Delete** ลบสินค้า | `products.html` / `products.js` | `db.from('products').delete().eq('id', id)` |
| เข้าสู่ระบบ / ออก | `index.html` / `login.js`, `app.js` | `db.auth.signInWithPassword({ email, password })`, `db.auth.signOut()` |

## กฎที่ฐานข้อมูลบังคับ (ใช้เขียนบทที่ 4.4)

- **ยังไม่ล็อกอิน (anon)**: อ่านหรือแก้ข้อมูลไม่ได้เลย
- **ล็อกอินแล้ว (authenticated)**: เพิ่ม แก้ไข ลบสินค้าได้ แต่ **แก้ `stock_quantity` ตรง ๆ ไม่ได้** ต้องทำผ่านรายการรับเข้า/เบิกออกเท่านั้น
- **ประวัติ `stock_transactions`**: เพิ่มได้อย่างเดียว แก้ไขหรือลบไม่ได้ และระบบบันทึกอีเมลผู้ทำรายการให้อัตโนมัติ (ปลอมไม่ได้)
- **Trigger ตัดสต็อก**: ล็อกแถวสินค้าก่อนคำนวณ กันกรณีสองคนเบิกพร้อมกัน และยกเลิกทั้งรายการถ้าเบิกเกินยอด
- **Constraint**: รหัสสินค้าห้ามซ้ำ, ราคา/ยอดคงเหลือห้ามติดลบ, จำนวนต้องมากกว่า 0, ประเภทต้องเป็น IN หรือ OUT

หน้าเว็บตั้งใจไม่กันการเบิกเกินยอดเอง (แค่แสดงคำเตือน) เพื่อให้ฐานข้อมูลเป็นคนปฏิเสธ
กฎจึงใช้ได้กับทุกช่องทาง ไม่ว่าจะเรียกจากเว็บ, API หรือ SQL

## กรณีทดสอบที่ลองได้ทันที (ใช้เขียนบทที่ 4.5)

ผลที่คาดหวังนับจากข้อมูลตัวอย่างเริ่มต้น ให้ทำตามลำดับข้อ (ทุกกรณีทดสอบแล้ว ได้ผลตามที่คาดหวัง)

| # | กรณีทดสอบ | ขั้นตอน | ผลที่คาดหวัง |
|---|---|---|---|
| 1 | Create สินค้าใหม่ | เพิ่ม DRK-005 น้ำส้ม 350 มล. จำนวนเริ่มต้น 12 | ขึ้นในรายการ คงเหลือ 12 และมีประวัติ "ยอดยกมา" |
| 2 | Read ค้นหา | พิมพ์ "น้ำ" ในช่องค้นหา | เหลือ 3 รายการ (น้ำดื่ม, น้ำอัดลม, น้ำส้ม) |
| 3 | Read กรองใกล้หมด | ติ๊ก "เฉพาะใกล้หมด" | เหลือ 4 รายการ (DRK-001, DRK-004, FOD-003, HOM-001) |
| 4 | Update แก้ราคา | แก้ราคา DRK-005 เป็น 25 | ราคาในรายการเปลี่ยนเป็น 25.00 |
| 5 | ข้อมูลผิด: เบิกเกินยอด | เบิก DRK-001 ออก 30 (คงเหลือ 25) | ปฏิเสธ "สต็อกไม่พอ: คงเหลือ 25 แต่ต้องการเบิก 30" ยอดไม่เปลี่ยน |
| 6 | Update ผ่านการเบิก | เบิก DRK-001 ออก 5 | สำเร็จ คงเหลือ 20 |
| 7 | Delete สินค้าที่ไม่มีประวัติ | เพิ่มสินค้าใหม่โดยไม่ใส่จำนวนเริ่มต้น แล้วกดลบ | ลบสำเร็จ |
| 8 | ข้อมูลผิด: รหัสซ้ำ | เพิ่มสินค้ารหัส DRK-001 | ปฏิเสธ "รหัสสินค้านี้มีอยู่แล้ว" |
| 9 | ข้อมูลผิด: ลบสินค้าที่มีประวัติ | กดลบ DRK-001 | ปฏิเสธ เพราะต้องเก็บประวัติไว้ตรวจสอบ |
| 10 | ข้อมูลผิด: จำนวนเป็น 0 / ราคาติดลบ | ใส่จำนวน 0 หรือราคา -1 | ฟอร์มแจ้งเตือน ไม่บันทึก |
| 11 | สิทธิ์: ยังไม่ล็อกอิน | ออกจากระบบ แล้วเปิด `products.html` ตรง ๆ | ถูกพากลับไปหน้าเข้าสู่ระบบ |

## แบ่งงานตามไฟล์ (ตัวอย่าง)

- **คนที่ 1 (Database)**: `supabase/schema.sql`, สร้างผู้ใช้, แคป Table Editor และ Schema Visualizer
- **คนที่ 2 (Frontend)**: ไฟล์ `.html` ทั้งหมดและ `css/style.css`
- **คนที่ 3 (Integration)**: ไฟล์ใน `js/` ทั้งหมด
- **คนที่ 4 (Test)**: ทดสอบตามตารางด้านบน แคปผลทุกกรณี
- **คนที่ 5 (Document)**: ใช้ตารางในไฟล์นี้เป็นโครงของบทที่ 4

## ความปลอดภัย

- `web/js/config.js` อยู่ใน `.gitignore` แล้ว จะไม่ถูกอัปขึ้น GitHub
- Publishable/anon key ใส่ในหน้าเว็บได้ เพราะสิทธิ์ถูกคุมด้วย RLS แต่ห้ามปิด RLS ก่อนนำขึ้นเว็บจริง
- ห้ามใส่ Secret key, service_role key หรือรหัสผ่านฐานข้อมูลในโค้ด รายงาน หรือสไลด์
